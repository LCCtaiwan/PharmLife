# PharmLife Hospital Career SPEC v0.6

> 狀態：`FREEZE`
> 變更：C-010
> 本文件取代 `hospital-vertical-slice-v0.5.md`，成為目前產品規格。
> 範圍：單一虛構台灣教學醫院，醫院藥師 25→65 歲完整職涯。
> 目前 runtime milestone：25–29 歲新人／PGY 已完成；30–65 歲依第 17 節順序後續實作。

## 1. 產品目標

玩家不是購買抽象數值，而是透過醫院分派、實際案件、培育與職涯抉擇，逐漸成為某一種醫院藥師。

核心問題是：

> 在一間有既定人力、制度與需求的醫院裡，我會如何完成工作、建立能力，並守住自己想要的人生？

第一個實作章節先完成 25→35 歲，以足夠深度驗證玩法。35 歲只做第一章職涯小結，不是人生結局。完整 Hospital Career 到 65 歲退休，或因劇情提早離開醫院執業。

## 2. 基準設定

- 場景是虛構台灣教學醫院，不使用真實雇主名稱，也不宣稱代表某一家醫院。
- 不同醫院的編制與工作不同；遊戲採衛福部訓練指引與公開醫院藥劑部資料中可見的代表性分工。
- 日常工作由單位與排班決定。玩家不能用行動點選擇要不要完成必要工作。
- 玩家控制具體案件的處理方式、培育志願、單位申請及職涯取捨；醫院控制缺額、排班及是否核准申請。
- 相同 RNG 版本、Seed 與選擇序列，必須重現相同職涯。

## 3. 明確排除

- 其他七條 Career。
- 學生篇、國考、育兒、置產、完整家庭財務、創業及非醫院職涯轉換。
- 自由走動、自由對話、真實病人資料或醫療建議。
- 把管理職當成唯一成功路線。
- v0.6 未通過玩法與手機驗收前，不發布正式站。

## 4. 完整職涯階段

| 年齡 | 階段 | 核心張力 |
|---|---|---|
| 25–29 | 新進藥師／PGY／受監督輪調 | 一邊學會制度，一邊跟上真正工作 |
| 30–39 | 可獨立作業藥師 | 廣度、深度、輪班與專業方向逐漸定型 |
| 40–49 | 資深第一線／專責／帶教／基層管理 | 專業、責任與影響力的取捨 |
| 50–59 | 高年資藥師／專責／管理 | 長期貢獻、健康、人力與制度變化 |
| 60–65 | 職涯後期 | 班別調整、經驗傳承與退休準備 |

可信賴的資深第一線藥師、專責藥師、帶教藥師與管理者都是完整職涯。未升管理職不等於失敗。

## 5. 核心遊戲循環

```text
醫院公布本年度單位、班別與人力狀況
→ 玩家處理 2–3 個代表性工作片段
→ 依能力、單位熟練度、資格、支援及當下狀態判定
→ 工作留下經驗、安全紀錄、關係與後續影響
→ 玩家提出一項培育或單位志願
→ 醫院依缺額、資格與工作紀錄核准、延後或拒絕
→ 年度報告說明工作、成長、薪資、健康及下年度分派
→ 35 歲第一章小結／65 歲職涯結算
```

工作片段只代表關鍵時刻，不模擬每張處方與每個班。失敗必須形成補救、追蹤或新局面，不能只是扣分後結束。

## 6. 工作分派

醫院根據職涯階段、已完成訓練、缺額及人力需求分派工作。

| 單位／業務 | 代表內容 |
|---|---|
| 門診調劑 | 受理及評估處方、調配、覆核、用藥指導、候藥壓力 |
| 住院調劑 | 單一劑量、出院帶藥、劑量與適當性評估、病房溝通 |
| 急診／夜間藥事 | 急件、有限人力、交班與優先順序 |
| 藥品供應與管理 | 採購、驗收、儲存、缺藥、管制藥品紀錄及回收 |
| 無菌與特殊調製 | 化療、TPN、PCA 等需特定訓練與防護的作業 |
| 臨床藥事服務 | 病人訪視、血中濃度監測、不良反應評估、諮詢及團隊巡房 |
| 藥品資訊／教學 | 文獻查詢、院內資訊、教學訓練及用藥安全資料 |

不是每位藥師都會做完所有業務，也不是所有單位一入職就能進入。

## 7. 成長模型

成長分成三層，不得再合併成一排泛用數值。

### 7.1 基礎能力

| 能力 | 內容 |
|---|---|
| `dispensing_verification` 調劑與核對 | 辨識、調配、覆核，以及工作量下的正確性 |
| `prescription_judgment` 處方判讀 | 適應症、劑量、肝腎功能、交互作用、禁忌、配伍及安定性 |
| `drug_knowledge` 藥品知識 | 常用與特殊藥品、處方集、資料檢索及證據使用 |
| `communication` 溝通協調 | 病人指導、醫護確認、交班及衝突處理 |
| `situational_response` 現場應變 | 急件、缺藥、系統故障、優先排序及升級處理 |
| `medication_safety` 藥事安全 | 異常通報、管制藥品、SOP、根因意識及風險預防 |

基礎能力主要從相關案件、回饋與訓練成長。玩家不在每年結束後任意分配通用能力點。

### 7.2 單位熟練度

每項業務各自記錄熟練階段：

```text
見習 → 受監督執行 → 可獨立作業 → 資深 → 可帶教
```

門診做得熟練，不代表自動精通無菌調製或臨床藥事服務。

### 7.3 資格與授權

部分工作必須完成指定訓練或評核。資格是獨立門檻，不是能力數字夠高就自動取得。

代表項目：

- 新進藥師／PGY 訓練模組；
- 某單位獨立排班資格；
- 無菌或危害性藥品調製訓練；
- 帶教資格；
- 院內臨床服務所需訓練。

資料模型必須讓不同醫院設定或後續平衡調整資格要求，不得在引擎中以特定事件 ID 寫死。

## 8. 身心狀態不是能力

以下是當下狀態，不得因一次疲勞而抹除已學會的專業能力：

- 疲勞；
- 壓力；
- 睡眠與恢復；
- 健康；
- 工作量；
- 連續夜班或不規則班別；
- Burnout 風險。

高年資藥師仍可能因不安全工作量或嚴重疲勞失常。休息改善狀態，但不會憑空增加專業能力。

## 9. 培育方式

能力與資格來自：

- 到職與 PGY 訓練；
- 受監督輪調；
- 實際處理相關案件；
- 資深藥師回饋；
- 院內課程與案例討論；
- 特殊業務訓練；
- 臨床訪視與跨團隊工作；
- 繼續教育；
- 異常事件檢討與流程改善。

在指定節點，玩家可以提出一項志願，例如申請輪調、申請特殊訓練、留在原單位深化、接受帶教準備，或暫時保留恢復時間。

志願不保證成功，需考量：

- 單位缺額及人力需求；
- 必要資格；
- 目前熟練度；
- 安全及出勤紀錄；
- 相關人物信任；
- Seed 決定的院內環境。

## 10. 職場人際

職場人際是 Hospital 核心系統，不是附加好感度。重要人物可包含同期藥師、帶教藥師、資深同事、新進藥師、主管，以及經常合作的醫師或護理師。

每段關係分開記錄：

- `professionalTrust` 專業信任：是否相信玩家的判斷、交班與承擔能力；
- `personalCloseness` 私人親近：工作以外是否願意支持及往來；
- `friction` 摩擦：競爭、不滿、價值衝突與未解問題；
- `sharedHistory` 共同經歷：一起處理過的事件及承諾；
- `currentRole` 目前處境：單位、職位、輪調、留停、離職或退休。

專業信任與私人親近不得合併。與玩家不親近的人仍可能高度信任其專業；好友也可能因工作方式產生嚴重衝突。

NPC 有自己的職涯與人生，會輪調、升遷、離職、留停或退休，不會永遠停在原職位等待玩家。共同經歷必須影響後續合作、競爭、求助、推薦及衝突事件。

## 11. 感情線

感情線是自願參與的長期人生線，不是強制任務，也不是伴侶提供固定增益的系統。

玩家可選擇開放戀愛事件或只維持朋友／單身路線。單身至退休是完整人生，不是失敗結局。

感情可能經歷：

```text
認識 → 產生好感／維持朋友
→ 約會 → 穩定交往
→ 同居／結婚／長期伴侶
→ 磨合、分開或持續相伴
```

感情事件著重人生安排：

- 輪班與臨時加班造成的相處問題；
- 是否為伴侶調整培訓、班別、居住或退休計畫；
- Burnout 時的支持、誤解或關係消耗；
- 雙方對工作、承諾及生活界線的差異。

邊界：

- 所有可發展感情的角色皆為成年虛構人物；
- 不設病人感情線；
- 不設直接主管與直屬部屬的感情線；
- 不以性別預設玩家可發展的對象；
- 選項下方同樣不預告後果；
- 感情結算與職涯結算分開，不以婚姻判定人生是否圓滿；
- v0.6 納入交往、同居、結婚與分開，但不展開育兒、置產或完整家庭財務模擬。

## 12. 工作片段與判定規則

每個片段必須先交代合理的單位、工作量及專業情境。選項只描述玩家要做什麼。

選擇前顯示：

- 情境與已知事實；
- 當前單位及相關身心狀態；
- 只有行動名稱的選項。

選項下方不得顯示能力加減、關係方向、成功率或後果提示。

選擇後才說明結果及原因。概念判定式為：

```text
相關基礎能力
+ 單位熟練度
+ 必要資格
+ 可用的同事／系統支援
+ Seed 不確定性
- 工作量、疲勞及情境難度
= 結果
```

隨機不能壓過準備。合格且熟練的藥師處理例行工作通常應該成功；不確定性主要用於資訊不完整、超量工作、衝突及罕見案件。

## 13. 代表事件族

- 處方疑義或不安全劑量；
- 外觀／名稱相似藥品與核對疏失；
- 門診塞車與病人溝通；
- 缺藥、回收或替代藥協調；
- 急診／夜班交接問題；
- 無菌調製偏差；
- 藥品不良反應評估與通報；
- 與其他醫療人員意見不同；
- 系統或設備中斷；
- 異常揭露、檢討及預防；
- 訓練評核、輪調申請及帶教責任。
- 同期合作、升遷競爭、同事離職及長期人情壓力；
- 自願觸發的認識、約會、承諾、磨合及分開。

每個事件族都可形成事件鏈；早期處理方式、工作紀錄與人物記憶必須改變後續情境。

## 14. 年度報告

年度報告優先呈現具體職涯紀錄，不用抽象總分取代內容：

- 工作單位與班別；
- 已完成訓練與獨立作業資格；
- 重要案件及後續結果；
- Near miss、異常及安全貢獻；
- 病人或團隊溝通結果；
- 單位熟練度變化；
- 薪資、夜班量與加班；
- 疲勞、健康、壓力及 Burnout 風險；
- 玩家志願與院方決定；
- 重要人際關係及共同經歷；
- 若玩家開啟感情線，伴侶關係的重要變化；
- 下一年度分派。

35 歲顯示「職涯第一章」：整理專業身分、已取得能力、重要關係、尚未完結的事件鏈及可能方向。不得顯示退休式人生結局卡。

## 15. 薪資與職涯進展

薪資維持分層：

```text
本薪 + 班別津貼 + 職務／特殊業務津貼 + 年終或獎金 = 年收入
```

升遷可能改變責任與薪資，但不是唯一進展。以下狀態分開記錄：

- 正式職等或職位；
- 單位熟練度；
- 專業資格；
- 工作信任與安全紀錄；
- 教學、專責或管理責任。

## 16. GameState 必要欄位

```ts
interface HospitalCareerState {
  age: number; // 25..65
  careerStage: string;
  currentAssignmentId: string;
  rosterProfile: string;
  coreCompetencies: Record<string, number>;
  assignmentProficiency: Record<string, ProficiencyLevel>;
  qualifications: string[];
  trainingProgress: Record<string, number>;
  condition: {
    fatigue: number;
    stress: number;
    health: number;
    burnoutRisk: number;
  };
  professionalRecord: {
    safetyEvents: string[];
    cases: string[];
    clearances: string[];
  };
  submittedPreferenceId?: string;
  assignmentHistory: string[];
  eventHistory: string[];
  choiceHistory: string[];
  colleagueStates: Record<string, ColleagueState>;
  relationshipPreference: "open" | "friends_only";
  romanceStates: Record<string, RomanceState>;
  compensationHistory: Compensation[];
  flags: string[];
}
```

`ColleagueState` 必須分開記錄專業信任、私人親近、摩擦、共同經歷及目前處境。`RomanceState` 必須記錄關係階段、承諾、衝突、共同生活決定及歷史旗標。

技術設計可調整命名與數值尺度，但三層成長、身心狀態分離，以及職場人際與感情關係分離是強制要求。

## 17. 實作順序

1. 以醫院分派與代表性工作片段取代現有 `annual direction`。
2. 分開實作基礎能力、單位熟練度、資格與身心狀態。
3. 實作持續性職場人際狀態，以及可完全關閉的感情線狀態。
4. 先完成 25–29 歲新人／PGY，至少包含一條職場人際鏈與一條自願感情鏈，驗證工作、案件、培育與人生是否形成有趣循環。
5. 使用同一系統延伸至 35 歲第一章小結，不加入其他 Career。
6. 第一章通過產品驗收後，再延伸 Hospital 至 65 歲。

不得用後期內容掩蓋前三年不好玩的問題。

## 18. 驗收條件

- 新進藥師不能獨立執行尚未完成必要訓練的工作。
- 必要工作由醫院分派，不得包裝成玩家購買的行動。
- 至少三種工作分派因案件、資格與狀態不同而有明顯玩法差異。
- 前期工作與培育會實際影響後續案件。
- 選項無後果副文字；結果畫面會解釋原因。
- 培育或輪調申請遭拒後仍有可玩後續，不是空白年度。
- 專業信任、私人親近與摩擦能各自變化，NPC 會因自己的職涯改變處境。
- 關閉感情線後仍能完整遊玩至 65 歲，且不受到隱性懲罰。
- 開啟感情線後，關係會受到排班、工作選擇與共同生活決定影響，而不是固定數值增益。
- 職涯結算與感情結算相互並列，不以單身或婚姻判定好壞。
- 35 歲產生章節小結，並保留可繼續至 65 歲的完整狀態。
- 65 歲結算能辨識第一線資深、專責、帶教與管理等職涯身分。
- 相同 Seed 與選擇能重現分派、判定及結果。
- 發布前必須通過單元測試、正式 build 及 390×844 瀏覽器流程。

## 19. v0.5 廢止項目

以下概念不得原樣帶入新版實作：

- 用一個抽象工作方向代表完整年度；
- 用四個可選「值班行動」代表必要工作；
- 把「提升調劑效率」當成具體行動；
- 把「經營主任信任」當成專業職務；
- 假設每位藥師都會做臨床專案或帶新人；
- 把 35 歲視為完整職涯結局。
- 把同事壓縮成單一好感度或固定功能角色；
- 把伴侶當成降低壓力的永久 Buff。
